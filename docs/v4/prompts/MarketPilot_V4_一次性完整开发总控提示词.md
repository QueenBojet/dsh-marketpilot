## 0. 唯一目标与工作模式

你担任资深 DeepSeek Harness (DSH) 插件架构师、TypeScript/React 全栈工程师、工程技术研究产品设计师、自动化测试工程师。**本次最终目标是交付一套可以在本机 DSH Desktop 中打开的、真实持久化和真实数据流转的 MarketPilot V4.0**，而不是空页面、静态演示或仅给出方案。

最终至少具备以下端到端操作：

**打开本机独立网页 → 选择或创建项目 → 上传新客户资料 → 看到候选变化并选择深度分析 → 人工采纳需求 → 针对工程问题开展本地/可用时联网研究 → 查看原始证据与报告重点圈注 → 将研究结论保存到项目 → 人工决定技术路线 → 维护结构化设备配置 → 真实核算 BOM / 成本 → 使用模板生成、审阅并导出真正的 DOCX → 人工发布 V1/V2 正式业务基线并对比历史变化。**

六个工作区均可单独使用，不得强制按上述顺序操作。可以只研究不生成方案、只维护成本不编写报告、仅生成技术方案而不包含报价。

**一次性执行规则：**

1. 先阅读本仓库和 `docs/v4/reference` 下的材料，再自主制定内部执行清单，并**立即编码**。不要只返回计划等待审批。

3. 不要因为任务很大就仅完成基础壳层；优先保证完整的**真实端到端业务闭环**，再做补充增强。对不可用外部服务给出诚实的降级状态，不用固定假数据填补。
4. 内部持续留痕（Git 小提交、`docs/v4/acceptance/` 实际测试结果），最终一次汇报整体完成情况。不得将“未经验证”“依赖外部配置”“测试替身通过”等等同于真实上线验收。

## 3. M1：现代、专业、可维护的独立工作台（必须高保真实现）

### 3.1 基础架构

- 将 V4 从 `v4-page.ts` 单体字面量迁移到**正式模块化 React + TypeScript 页面**，使用项目实际支持的前端打包方式和 DSH 同源静态资源服务。必须将页面状态、可复用组件、API、模型服务、数据查询与样式拆分；拒绝把新功能继续塞进单段 HTML 字符串。
- 优先复用现有服务层、受控 Tools 与 Human Gate；有 DSH 原生面板模块加载限制时，独立页使用真正适用的浏览器构建入口，禁止错误共享宿主冻结 module table 的专有运行时模块。
- 独立入口由插件菜单/既有 MarketPilot 界面点击后打开新的**浏览器网页**，本机 DSH 作为 Host 提供 API，不需要重新配置一套独立 AI API Key。支持刷新、返回项目列表、浏览器重开、项目切换、运行中任务恢复状态。

### 3.2 六个工作区和视觉

**项目总览 / 资料与变更 / 智能研究 / 方案与决策 / 成本与报价 / 文档与交付**必须是可自由访问的工作区，另外有全局项目列表、运行记录和必要的系统设置。不得强制线性 S0—S7，也不得只给每个栏目一个空白卡片。

视觉遵循参考 HTML 和截图；主方向是高质量专业 SaaS：导航深海蓝 `#101C2E`、画布 `#F6F8FB`、主操作蓝 `#3064DF`、青绿 `#11A5A4`、12～16px 圆角、克制阴影、明确标题层级。桌面 1440px 高保真，1024px 不溢出，移动端自适应。适当保留严肃工程软件的信息密度：路线使用卡片，BOM 使用可编辑表格，文档呈纸张预览。重要状态清楚但不滥用颜色；不做霓虹大屏、不把外部网上不相关图片当技术配图。

UI 必备：加载/空态/失败/重试，右侧来源抽屉、模型选择、长任务运行状态，确认/拒绝弹窗，待处理风险，自动保存说明，键盘操作与基础无障碍。**所有可见按钮必须真实生效或者明确禁用并解释原因。**

### 3.3 模型、执行与安全

- 模型选项优先读取 DSH **实际注册且可用**的 Provider、模型与思考强度；全局默认→项目偏好→本次覆盖；未知可用性明确展示。不承诺任意模型支持所有强度。实际 route 进入本次 Task/Run 记录，允许核查。
- 原模型接口和子 Agent 调用路径必须以官方 DSH 宿主实测为准；用户切换模型后，下次任务生效，不改变执行中的任务。
- Agent 长任务支持运行/等待人审/失败/取消/返回继续查看。任务历史不应只存浏览器内存；合理复用现有 WorkflowRun，必要时持久化执行视图。
- 同源且仅本机 loopback；Host 的会话验证、请求校验/CSRF、CSP/XSS 防护；文件名、原文、链接、Markdown/HTML 不能直接执行脚本。实现合理的上传大小与类型限制以及跨项目授权验证。

## 4. M2：资料增量分析 + 真正可复用的智能研究

### 4.1 项目知识对象（可在现有领域模型上扩展）

设计持久对象与实体链接，至少覆盖：`IntakeBatch`/资料事件、`ChangeProposal`/变化建议、`ResearchQuestion`/研究问题、`ResearchRun`、`Finding`/研究结论、`ImpactLink`/影响关系，链接已有 Requirement/Evidence/Alternative/Decision/Document。保存项目 ID、稳定记录 ID、来源页段/摘录/哈希、时间、人审动作、证据状态和工作状态。按现有 `stateSchema` strict 校验和 JSON/SQLite 后端做**向后兼容或显式可恢复迁移**，不要求旧项目立刻生成 V1。

### 4.2 客户资料变化

- 新增批次可上传文本/PDF/DOCX/常用表格、也可录入会议纪要的人工摘要。优先提供真实解析（包括基本文本、表格和来源页段），无法准确解析扫描件/复杂表格时明确标注限制，不得悄悄丢字段。合理校验 MIME/扩展名、上限和文件安全。
- 上传完成生成**轻量候选变化摘要**（新增、修改、矛盾、背景补充），低成本可用时自动运行，复杂情况提示人工检查。不自动发起耗时深度研究，也不直接覆盖正式 Requirement。
- 人工点击才启动深度差异/影响分析；逐条采纳、忽略、待澄清、转研究问题。保留新旧原文与来源。不把“资料信息”“确认的需求”“已发布方案”混为一体。
- 直接链接带来真实约束的对象与 AI 推测的间接影响分别标明；允许人工确认“无需修改”并消除重复提醒。

### 4.3 技术研究工作区

- 三栏：左侧持续技术问题/资料目录，中间结构化研究报告与来源标记，右侧**真正可持续多轮对话**的项目 AI 助手。上下文由当前研究问题/项目范围提供；每轮保存，重新打开可以继续研究，更换模型不丢会话。
- AI 先建议研究计划，用户可编辑并确认后执行；不要为每一个普通问题都强制复杂表单。支持本地资料研究、真实联网搜索及二者联合。
- 优先复用 DSH `web.search`/`web.fetch` 与现有研究工具，核对真实 Provider 是否启用。只有读取并保存原文正文后，才标为“已获取来源”；单纯搜索摘要/模型常识不得冒充来源。维护 URL、标题、时间、摘录/定位、适用条件、引用关系、内容哈希/快照；失败或失效如实展示。
- 报告重点参数、条件与结论做**克制圈注**；点击打开证据抽屉并可去真实来源网页/PDF 页段。网页无法精确定位则展示原文片段与来源，不可假装精准跳转。
- AI 提取 Finding 候选，人可采纳/改写/忽略，也可手动选中文字保存。**人工采纳与来源核验状态独立**；新资料影响旧 Finding 时标记需复核，历史版本保留。
- 自由对话不允许直接绕过 Human Gate 修改正式决策或发布正式文档。

联网 Provider 真不可用时：应用必须有明确能力状态和真实的本地研究完整路径，并说明联网未验收；不得插入虚假网页、引用、供应商资料或回避错误。

## 5. M3：人工技术决策 + 配置 + BOM/价格 + 正式 V1/V2

- 技术路线候选沿用已有 Alternative 和人工 Decision Gate；可以持续比较与再决策，旧 Decision 不覆盖。研究 Finding、客户需求和方案设备要能互查。
- 配置使用持久化结构化行：系统/功能分组、设备名称/型号、关键参数、数量、单位、接口、安装方式、关联的需求/证据/决策、价格状态。配置变化在当前**工作草稿**生效，触发依赖图的成本/文档“需复核”；不会自行改写正式 V1。
- 建立真实可维护 BOM/CostEstimate/Quotation 对象：设备成本、安装集成、工程服务、备用项、税费/预留；价格记录币种、来源、有效期、报价对象及估算/正式区分。多币种和汇率不足时禁止误导性的合计。
- **金额由确定性高精度计算代码产生**，定义小数精度、舍入、税费与换汇顺序；不能把 AI 生成金额当精确报价。缺价格可标待询价/内部粗估，但不能冒充供应商报价。
- BOM 关联 Configuration：配置数量/价格改变，实时重算并失效旧审核。可选择“技术方案基线”或“含成本完整方案包”；两者发布检查不同，用户不做报价也能保存技术版。
- Baseline 一次发布冻结需求、研究/决策引用、技术配置、成本/报价版本、文档关联快照，审查快照/时间/操作记录。发布必须由真实用户确认，明确区分 Draft/Review/Published；**已发布 V1/V2 不可原地改动**，新增变化只在草稿上。
- 版本对比是业务差异（需求、技术路线、设备、成本、文档），不仅 Markdown diff。历史 CALM 项目升级后应仍能直接查看现存 Artifact 和 Run。

## 6. M4：真实 DOCX 模板 + 可编辑方案成果

- 允许上传并管理真实公司 DOCX 模板，设置章节/占位符映射；同时**提供一个可实际运行、可测试的通用默认 DOCX 模板**，因为用户当前可能尚未提供正式公司模板。模板必须可替换，不能以等待真实公司模板为理由停工。
- 项目要求、研究结论、技术决策、设备配置、BOM、引用与当前基线可被映射至章节。生成内容层和格式层分离；对变化章节可提出 AI 修订草稿，用户审核后替换，未受影响章节尽可能保留。
- 输出真正可编辑的 `.docx`（有 Word 结构和样式、表格、标题、页眉页脚、中文排版等），并验证可解包/打开和渲染基本正确。不能用纯文本改 `.docx` 扩展名冒充生成成功。后续 PDF 仅在真实生成/验证条件具备时启用。
- 文档修改使旧审阅失效；明确区分“已审核”“已导出”“确实已对外发送”。不许生成 Artifact 后自动记作客户已收到。
- 提供版本对比、章节依赖、编辑审阅和实际下载；不要求用户在不同版本的 Word 间自行复制完整文件。

## 7. M5：完整产品体验与回归/端到端验收（不要省略）

### 7.1 必须覆盖的 CALM 测试故事

使用**隔离的合成 CALM fixture**，不要写入真实船东项目：

1. 创建项目，录入初始技术条件，保存研究资料并确认需求。
2. 建立水下漏油监测研究问题，联合现有资料开展多轮 AI 研究；若真实联网可用，对至少一个实际网页来源进行搜索、Fetch、正文与 URL 证据校验；否则明确标为未验收。
3. 比较两条技术路线，记录人工确认 Decision，并给出方案配置。
4. 输入有出处的**测试价格**（显著标明测试数据），生成 BOM 和项目成本；检查金额与确定性公式一致。
5. 按默认模板形成可编辑 Word 方案草稿，审阅后发布技术 V1 或含成本的 V1 包。
6. 再上传一批与先前存在差异的客户要求，展示变化来源/影响，人工采纳并局部修订技术配置。
7. 验证成本自动更新、旧成本/文档审核失效、相关章节修订，人工发布 V2。
8. 对照 V1/V2 的需求/配置/BOM/文档差异；重启 DSH 再打开，所有对象、日志、引用和历史版本依然存在。
9. 旧版真实 CALM 项目只读打开核验，验证旧 V3 Artifact、决策、需求、证据和 ID 未损坏。

### 7.2 测试类型与必查问题

- 每个内部工作包后实际运行 `pnpm typecheck`、`pnpm test`、`pnpm build` 及 repo 文档所要求的 bundle/隔离 smoke。解决失败而不是掩盖或跳过。
- 自动化至少覆盖数据模式兼容、跨项目隔离、来源/引用完整性、模型路由、Human Gate 不能自动批准、基线冻结、BOM 金额精度、失效传播、文档真实文件结构、HTTP 上传限制、API 错误、XSS/CSRF/SSRF、失败恢复与执行取消。
- **需要实际 GUI 视觉验证**：官方 DSH Desktop/Web Profile 真实加载独立页，在 1440px、1024px 及移动宽度对照参考五页截图，检查没有错位/整体横向溢出、操作按钮确实起效。若不具备浏览器控制，请记录未验证，不要伪造截图。
- 真实模型/联网与离线 fixture 测试分类记录。V3.3 曾出现 `zai/glm-5.3-flash/max` 真实生成，但这不表示 V4 已经通过对应的联网验收。
- 遇到阻塞外部 Provider/公司正式模板，不要暂停剩余开发；用真实可运行的本地能力/默认模板完成整体应用并清楚列出受阻功能。**禁止用虚构网络研究或价格替代真实事实。**
