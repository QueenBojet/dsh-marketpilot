# MarketPilot 智策 V4.0｜全流程页面与交互规格 V2.0

> 状态：交互设计讨论稿；不是开发任务单、Codex 提示词或现有 V3.4 功能声明。
> 场景：CALM 单点系泊漏油监测。HTML 原型中的客户资料、技术路线、设备配置、单价及金额均为虚构示例，不可用于真实技术决策与报价。
> 已确认决策：1C 新资料轻量提示＋人工启动深度分析；2B 研究报告为中心＋AI 助手；3B 草稿持续修改＋人工发布；4A 本机独立网页，复用 DSH。

## 1. 总体信息架构

全局导航：工作台、我的项目、研究资料库、运行记录、设置。

项目内导航：项目总览、资料与变更、智能研究、方案与决策、成本与报价、文档与交付。

六个项目页面是**自由访问的工作域，不是强制线性流程**。可研究而不生成方案，可做技术方案而不附商务报价，也可只针对已有设备清单更新成本。右侧 AI 助手继承项目与当前工作对象上下文；研究页面采用常驻可收起侧栏，其他页面可由浮动入口或抽屉调用。用户选择 Provider/模型/思考强度后，配置仅对下次执行生效，实际可用选项取自 DSH。

## 2. 已有两个页面的视觉与交互规范

### 2.1 项目总览

- 顶部：当前项目、全局通知及连接状态；首屏业务目标与两个高频操作「继续研究」「导入新资料」。
- 主区：当前正式基线、待确认变更、活跃技术问题、已采纳研究结论。数据数量不是完成度评价。
- 左主栏：最近客户信息摘要，点击「查看变化与影响」打开右侧核查抽屉；技术问题列表可直达研究主题。
- 右栏：正式基线卡片、最近工作记录。正式基线永远只读；工作草稿状态独立展示。
- 导入：允许录入文件、来源、批次和补充备注。轻量识别只产生可能变化的提示；深度分析由用户启动。重复文件、解析失败、来源不明和冲突信息均需显示明确状态。

### 2.2 智能研究空间

- 三栏：左侧技术问题与来源；中间结构化研究报告；右侧 AI 对话与模型选项。中小屏 AI 助手以浮动侧栏呈现。
- 研究入口：用户可以直接提问，也可以先审阅计划再启动联合本地/联网研究。仅在获得真实网页正文或原始文档后，才能将来源标为已获取。
- 圈注：正文的关键条件、参数和结论采用少量克制的轮廓强调。点击弹出证据抽屉，列出原始段落、来源名、URL、抓取时间、适用条件和证据级别。
- 保存：AI 提出候选 Finding，用户可采纳、修改或忽略；也可以手选文字保存。采纳状态与证据真实性分别保存。
- 结果：可把 Finding 关联到 Requirement、Question、Decision 或 Configuration，后续变更可以触发影响核查。
- 失败兜底：无法联网时明确展示仅使用本地资料；未访问过的网址不可展示为已验证；网页文本定位失败时保留片段和快照，不伪称已定位成功。

## 3. 新增页面：方案与决策

### 3.1 页面组成

**顶栏**：方案与决策、研究依据入口、发布新基线按钮。

**当前工作概况**：正式基线、草稿、人工路线确认状态，强调 V1 与草稿的区别。

**主工作区三种标签**：
1. 技术路线：候选 A / B 卡片，展示适用条件、优势、局限、证据和未决问题；选择候选仅更新工作草稿，不自动确认。
2. 设备配置：结构化配置项（名称、型号、数量、单位、关键参数、需求关联、证据状态、价格状态）。配置变动影响成本与文档审核。
3. 版本差异：按需求、研究结论、决策、设备、成本和文档对象展示业务级差异，不只是 Word 逐字比较。

**右栏**：人工决策记录、路线选择理由、已确认来源，以及建议继续处理的问题。真正的技术决策需要有明确的人员确认行为；不能凭 AI 候选得分自动确认。

### 3.2 交互与规则

- 「选择路线」：仅将候选路线写入草稿；一旦与此前已确认的路线不同，当前草稿的路线确认状态失效。
- 「确认本轮技术路线」：弹出人工审核层，要求记录选择理由。未确认前可自由修改，历史决策不覆盖。
- 「编辑配置」：抽屉编辑数量、型号、参数及价格来源；保存时重新计算依赖关系，必要时将成本核查、文档审核置为待核查。
- 「发布方案基线」：打开检查弹窗，明确本次发布类型。推荐至少区分**技术方案基线**（技术决策＋配置＋文档）与**含成本测算的完整方案包**（增加成本人工核查）；不强制所有技术任务必须完成报价才能发布。
- 发布成功：冻结快照，包括选定的需求、证据引用、人工决策、配置、包含的成本版本与文档版本。后续修改进入新草稿；历史 V1/V2 不原地覆盖。

## 4. 新增页面：成本与报价

### 4.1 页面组成

顶部三项信息：直接成本小计、风险预留规则、当前人工核查状态。

左栏可编辑 BOM/费用明细：配置项、数量、单位、价格、币种、价格来源、费用小计、待询价状态；下方显示成本构成条。

右栏显示工作草稿合计及限制条件，列出供应商正式报价、税费与利润、汇率/有效期等可能缺失的依据，并提供「确认本轮测算」入口。

### 4.2 核心业务规则

- 金额由确定性公式计算：数量×单价，再按清晰配置的费用规则计算；AI 不直接输出不可解释的汇总金额。
- `设备项`和`成本行`建立一对多或多对一映射的能力：一台设备可能对应采购、安装和集成费用，多个配置项也可能共用一项工程服务。
- 价格至少保存币种、来源类型、报价日期、有效期、适用数量、含税属性和可追溯附件；尚未询价的金额标为估算。
- 成本草稿审核 ≠ 供应商报价已核验 ≠ 对外商务报价已批准，界面必须区分。
- 设备数量、技术路线或价格发生变化时，标出需要重新核查的成本项，并使与之依赖的原审核标记失效。
- 允许完成技术研究或技术方案而不提供完整价格；有商务交付要求时才启用相关发布检查。

### 4.3 异常处理

数量不能为负或非整数；价格不能为负；缺失报价来源允许内部估算但限制对外用途；多币种、税率和汇率缺失时不得自动输出有效商务报价。

## 5. 新增页面：文档与交付

### 5.1 页面组成

顶部：当前模板、待同步章节数、草稿审阅状态；主要操作「选择模板」「审阅文档草稿」。

左栏：文档切换（技术方案、成本说明、版本变化摘要）；列出决策与成本数据的状态及受影响章节更新建议。

右栏：A4 纸张感实时预览，可在未来延伸为章节编辑、批注与差异比较；目标支持 DOCX 模板并将章节结构映射到项目知识对象。

### 5.2 核心操作

- 「选择模板」：对正式模板应保留标题、段落、表格样式、页眉页脚、封面与目录；原型只模拟模板选择。
- 「更新受影响章节」：AI 只对相关章节提出修改草稿，不默默覆盖已审阅文档；受影响的版本依赖可以追溯到需求或配置变动。
- 「审阅草稿」：工程师逐项检查技术内容、来源限制、价格引用及变更范围；审阅结果绑定特定文档快照。更新内容后必须重新审阅。
- 「导出」：正式系统目标为 DOCX/PDF 和必要的报价表导出，记录是否确实导出或对外发送。原型不提供真实格式生成。

## 6. 完整点击路径（贯穿 CALM 示例）

1. 项目总览 → 「导入新资料」 → 显示轻量识别变化 → 用户启动深度分析。
2. 资料与变更 → 审阅来源、新旧要求与可能影响 → 用户采纳/忽略/待澄清。
3. 智能研究 → 围绕受影响的技术问题继续研究 → 查看原文来源 → 保存经人工采纳的研究结论。
4. 方案与决策 → 比较候选技术路线 → 人工确认路线与理由 → 修改结构化设备配置。
5. 成本与报价 → 检查联动 BOM → 更新数量或价格 → 核对来源与成本范围，人工记录测算审阅。
6. 文档与交付 → 根据当前配置和成本更新受影响章节 → 审阅草稿。
7. 方案与决策 → 选择发布范围（技术方案 / 完整方案包）→ 审核对应必需项 → 人工发布 V2；V1 保持只读。

**这是一条可展示的完整业务故事，并不构成强制工作流。** 用户可自由跳转、只做研究或只做报价；发布门槛按交付类型变化。

## 7. 设计系统与现代化视觉规范

- 导航：深海蓝 `#101C2E`，选中项使用青蓝左侧高亮，内容画布 `#F6F8FB`；主操作蓝 `#3064DF`，次强调青绿 `#11A5A4`。
- 字体：Inter / 系统 UI 字体 / 苹方或微软雅黑；标题大而清晰，正文适中，次要说明使用克制低对比色。
- 组件：圆角 10–16px、轻柔阴影、无多余渐变；大块空白用于内容分组，避免传统表格堆砌。BOM 对于高信息密度仍使用表格。
- 重点圈注：来源与参数重点可使用轻描边、微底色及外侧标记；不做满屏手绘划线。
- 弹窗：选择/发布等需要确定操作使用模态层；来源详情、编辑配置等上下文检查使用抽屉；连续研究及文档阅读使用主画布。
- 响应式：桌面 1440px 优先；1200px 左右改为单栏上下叠放；窄屏隐藏永久侧栏，保留底部导航，数据表格在自身容器内横向滚动。
- 状态反馈：任何非真实功能必须标记“演示/待接入”，任何后台异步任务必须提供运行、等待、失败、恢复及取消状态。

## 8. 原型已覆盖与尚未覆盖

### 已覆盖（仅前端交互模拟）

- 六个项目工作域的导航及关键页面布局（项目总览、资料变更、研究、方案、成本、文档）。
- 资料导入、变更核查、研究计划、来源抽屉、研究结论采纳。
- 路线切换、人工确认理由、配置数量和演示单价编辑、成本确定性重算。
- 成本核查、文档选择、章节同步示意、文档审阅、发布检查及基线快照。
- 桌面浏览器测试：完整流程可执行，无页面 JavaScript 错误；移动端关键工作区未发生整体横向溢出。

### 未覆盖（正式产品需要实现及验收）

- DSH 真实 Provider/模型路由和思考强度映射、项目会话持久化。
- 真实联网检索、网页抓取、来源真实性核查与精确证据定位。
- PDF/DOCX/XLSX 解析、OCR/表格/附件读取及安全策略。
- 可靠的需求变更影响推理、正式业务关系持久化、历史数据迁移。
- 供应商报价导入、币种汇率税费配置、真实报价审批。
- DOCX 模板高保真渲染、编辑、导出、实际交付记录。
- 生产级授权、会话、安全防护及跨任务异步执行。

## 9. 下一轮评审的三个重点

1. 页面视觉是否符合用户希望的“现代、专业、精致”，尤其技术方案卡片、报价明细和纸张预览的比例。
2. 配置→成本→文档的交互是否足够直接，是否需要将常用操作做成同屏联动编辑。
3. 用户常用的 CALM 方案和报价模板实际结构是什么，决定后续最先支持哪一种真实文档模板。
