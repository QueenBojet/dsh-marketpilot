## 1. 审计目标与核心原则

MarketPilot V4（智策）是面向工业监测、船舶海工、能源安全与环保装备领域的**工程方案与报价 AI 协同工作台**。与消费级聊天工具不同，工程方案交付对**可追溯性、依据时效性、人工权责边界（Human Gate）、确定性成本核算、正式基线不可篡改性**具有严苛的红线要求。

本次审计遵循两大核心原则：
1. **严格保护工程治理红线（零弱化）**：
   - DSH 模型选择与显式路由（禁止把 API Key、Base URL 暴露到前端 UI，严格保留 `dsh` provider/model/reasoningEffort 路由与错误披露）。
   - 研究来源诚实性（`fetched` 必须包含真实抓取快照与哈希；引用证据必须在原文中逐字可定位；无 Web Provider 时诚实披露不可用）。
   - Human Gate 人工确认机制（所有改变权威业务状态的操作必须通过 `marketpilot_*` 受控工具并在弹出的审核门禁中由人工确认，支持取消与回退）。
   - 确定性成本核算（整数厘/基点运算，严禁 AI 估算充当真实报价，`test_data` 强阻断供应商核验与对外发送，外币缺汇率隐藏总价）。
   - 文档审核与基线不可变性（严格区分“已人工审核 / 当前版本已导出 / 已对外发送”；已人工编辑章节绝不被 AI 覆盖；V1/V2 基线一旦发布永久只读）。
2. **消除非必要的交互摩擦（做减法与提效）**：
   - 严苛区分**“业务必需门槛（Engineering Governance Gates）”**与**“可优化的交互摩擦（UI/UX Friction）”**。
   - 通过全局阶段导航、上下文内联预检、跨模块快捷跳转、结构化 Markdown 渲染、一键配置转 BOM、主次分层折叠，让工程师无需在 7 个页面间反复迷航。

## 2. 三类核心用户路径全链路走查

### 2.1 路径 A：新建 V4 引导式探索项目（11 步端到端正向主路径）

| 阶段序号 | 业务阶段 | 触发入口与路由 | 核心数据实体与状态流转 | 必需的工程治理门槛（不可省） | 原版前端交互痛点（审计发现） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Step 01** | **创建项目** | `#/home` 或 `#/projects` → 新建项目 | `Project` + `v4.discovery`（默认开启引导探索模式） | 项目名称非空校验 | 新建后仅停留在列表或空壳总览，缺少明确的“第一步去哪里”引导卡片 |
| **Step 02** | **多轮需求访谈** | `#/discovery?p=:id` → 发送访谈对话 | `v4.messages(thread='discovery')` → 生成 `v4.discovery.proposal`（候选简报） | AI 仅生成 `proposal` 候选提议，**绝不直接改写已确认简报或工程需求**；每轮最多追问 3 个聚焦问题 | 访谈对话区与右侧简报编辑区高度失衡；AI 提议与当前工作草稿的差异缺少醒目对比提示 |
| **Step 03** | **人工确认需求简报** | `#/discovery?p=:id` → 保存并点击「人工确认需求简报」 | 调用 `marketpilot_v4_brief_confirm` → 写入 `brief.review` + 自动同步 `acceptance` 为 `confirmed` 需求 | 目标、场景、范围、约束与至少 1 条可验证验收标准齐备，且须通过 Human Gate | 确认简报后缺少一键前往“资料与支撑”或“多路线初筛”的上下文接力按钮；保存简报草稿导致确认失效时缺少顶部联动提示 |
| **Step 04** | **上传资料与固化精选支撑** | `#/change?p=:id` → 上传资料 → 新增结构化摘要 → 人工固化 | `documents` + `v4.intakeBatches`（仅保留原文，不自动按行拆需求）→ `v4.supportNotes(draft -> fixed)` | 关联原文时摘录必须在文档中**可逐字定位**；必须经 `marketpilot_v4_support_fix` 人工固化后才进入 AI 上下文 | 原版将“V4 精选支撑摘要”与“V3 历史候选变更/拆条”平铺混杂，用户难以理解为何上传文件后没有自动生成需求 |
| **Step 05** | **第一轮广泛技术路线初筛** | `#/solution?p=:id` → 「开始多路线头脑风暴」 | 调用 `marketpilot_v4_brainstorm(phase='initial')` → 生成 ≥3 条候选路线 `alternatives` 及 `explorations[initial]` | 必须先确认需求简报；若简报或固化支撑后续发生变更，`initialCurrent` 自动置为 `false` | 初筛工程推理综述 `e.summary` 未经 Markdown 渲染（裸露 `**` 与列表符）；生成定向研究问题后缺少直达研究页面的内联锚点 |
| **Step 06** | **分路线定向技术研究与证据核实** | `#/research?p=:id` → 确认研究计划 → AI 检索与报告 → 采纳/核实结论 | `v4.questions`（绑定 `alternativeIds` + `direction`）→ `v4.runs` + `v4.sources` → `v4.findings` | 研究计划须先确认；结论采纳（`adopted`）与证据核实（`verified`）必须分别经 Human Gate 审核且原文引用可定位 | 左侧问题列表信息过密，缺少关联技术路线标签与方向标签；研究报告长文缺少结构化阅读容器；新建/编辑问题弹窗字段拥挤 |
| **Step 07** | **第二轮综合判断与路线重组** | `#/solution?p=:id` → 「综合判断与二次头脑风暴」 | 调用 `marketpilot_v4_brainstorm(phase='synthesis')` → 综合 ≥2 个不同研究方向报告，重组生成最终候选路线 | 必须存在当前有效初筛 + **至少 2 个不同具体方向（`distinctDirs >= 2`）**的有效研究报告 | **严重视觉层级倒置**：当进入第 5 阶段（已有第二轮综合结果）时，第一轮 4 张大卡片仍霸占首屏，把第二轮综合候选与 Human Gate 挤到屏幕下方，且在特定容器组合下 `.section-spacer` 固定高度造成布局重叠隐患 |
| **Step 08** | **人工路线决策（Human Gate）** | `#/solution?p=:id` → 选为草稿路线 → 「人工确认」 | `v4.draftRoute` → 调用 `marketpilot_v4_route_confirm` → 生成 `Decision` 并绑定 `confirmedAlternativeId` | 引导模式下必须从第二轮综合候选路线中选择；必须填写选择理由并勾选覆盖的已确认需求 | 候选路线过多时仅能逐卡滚动，缺少横向对比矩阵（系统组成/优势/局限与风险/待核实项同屏比选） |
| **Step 09** | **维护方案设备配置清单** | `#/solution?p=:id` → 切换「设备配置」Tab → 新增/编辑配置项 | `v4.configItems`（分组、型号、参数、数量、接口、安装、关联需求与研究结论） | 数量必须为非负安全整数；修改配置自动使依赖的成本审核与文档审核失效 | 配置清单保存后缺少一键跳转到“成本与报价”并自动同步生成对应 BOM 成本行的桥梁 |
| **Step 10** | **确定性 BOM 成本核算与三阶审核** | `#/cost?p=:id` → 新增/同步成本行 → 执行三阶审核 | `v4.costLines` + `v4.costSettings` → 确定性计算 `ov.cost.result` → `marketpilot_v4_cost_review` | `test_data` 价格严禁通过“供应商报价已核验”；缺价格/缺汇率阻断对外报价审批；上游变动自动置 `stale` | 需要手工重复录入与设备配置同名的 BOM 行；缺少直观的成本构成占比条与未关联配置项自动检测提示 |
| **Step 11** | **按公司 Word 模板撰写、审核、导出与发布 V1/V2** | `#/deliver?p=:id` → 上传 `.docx` 模板 → 按模板撰写 → 接受章节建议 → 人工审核 → 导出 DOCX → 发布正式版本 | `v4.templates` + `v4.docs`（`sections` 含 `proposal` 与 `editedByHuman`）→ `exports` → `sent` → `v4.baselines(V1/V2)` | 人工编辑过的章节绝不被 AI 覆盖（仅生成 `proposal` 建议）；三态严格分离（审核/导出/外发）；技术方案基线不含成本，完整基线须含有效成本审核 | 左侧文档列表与右侧 A4 审阅区宽度比例不协调；缺少带行号的章节级待审阅建议卡片与一键接受全部建议入口 |

### 2.3 路径 C：逆流程、异常流与防呆机制审计（9 大关键场景）

1. **未配置模型或 DSH Provider 不可用（`!ov.capabilities.model.available`）**：
   - **系统行为**：所有依赖 AI 的按钮（访谈发送、头脑风暴、AI 拟定计划、AI 检索撰写、按模板撰写、章节 AI 修订）自动禁用，并通过 `Btn showReason` 在按钮下方直接显示具体原因（如 `请启用 Harness subagents/spawn` 或所选 Provider 不可用），同时所有手工录入、确定性成本计算、人工审核与 DOCX 导出功能保持 100% 可用。
2. **未配置联网搜索 Provider（`!ov.capabilities.research.available`）**：
   - **系统行为**：顶部状态栏诚实显示 `仅本地知识库`；研究计划支持切换为 `local`（仅本地资料研究），绝不伪造网页搜索结果。
3. **跨项目快速切换防串味（`tests/v4-store-project-switch.spec.tsx`）**：
   - **系统行为**：在 `store.tsx` 中，当 `pid` 变化时立即清空旧项目 `ov` 快照并递增请求代数 `reqId`，丢弃慢速返回的旧项目响应，彻底杜绝跨项目私有数据残留或闪烁。
4. **耗时模型任务中途取消（`POST /marketpilot/api/executions/:callId/cancel`）**：
   - **系统行为**：底部浮动运行条实时显示执行状态与「取消运行」按钮；取消后后端 `AbortSignal` 立即中断，不会写入半成品简报、探索或研究报告，运行记录诚实标记为 `cancelled`。
5. **生成期间上游依据并发变更（Stale Snapshot Guard）**：
   - **系统行为**：访谈回复、研究报告或 Word 模板撰写在模型运行期间若检测到对话、精选支撑或项目依据指纹发生变化，后端拒绝提交过期产物并返回明确提示。
6. **用户在 Human Gate 弹窗点击「退回修改 / 取消」**：
   - **系统行为**：`Modal` 置顶展示完整的待确认动作与 JSON 提案明细；用户点击「退回修改」后，业务状态保持原样不变，无脏数据残留。
7. **需求简报或固化支撑修改导致下游探索自动失效**：
   - **系统行为**：修改已确认简报或新增/修改固化支撑后，`discoveryStatus.initialCurrent` / `synthesisCurrent` 自动变为 `false`；全局 `WorkflowStepper` 下方立即弹出琥珀色「上游依据联动提醒」横幅，引导工程师按序更新初筛与综合判断。
8. **路线或设备配置修改导致成本与文档审核自动失效**：
   - **系统行为**：更换草稿路线或增删改 `configItems` / `costLines` 后，由于 `boundHash` 不再匹配当前指纹，成本审核（`ov.cost.reviews`）与文档审核（`doc.review`）自动变为 `stale`（已过期需复审），发布正式基线按钮自动禁用并给出具体阻塞原因。
9. **测试价格（`test_data`）与外币缺失汇率防呆**：
   - **系统行为**：只要存在 1 行 `sourceType === 'test_data'`，页面顶部即显示醒目警示横幅，`② 供应商报价已核验` 审核按钮强制禁用；若存在外币行且未配置对本位币汇率，系统自动隐藏总价（显示 `无合计`）并阻断 `③ 对外报价已批准`。
