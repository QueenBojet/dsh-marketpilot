# MarketPilot V4（智策）优化前后操作效率评估与测量方案（`EFFICIENCY_MEASUREMENT.md`）

- **文档目的**：提供客观、可复现、方法论严谨的优化前后工程效率对比框架，严格区分**“界面交互路径收敛指标（Deterministic UI Path Metrics）”**与**“真人操作耗时实验指标（Human-in-the-Loop Timing Protocol）”**，杜绝无真实样本支撑的虚假百分比宣传。

---

## 1. 指标分类与诚实性原则

在评估 AI 工程工作台的前端优化效果时，必须严格区分两类不同性质的指标：
1. **确定性交互路径与首屏信息可达性指标（已实测验证）**：
   - 指完成同一标准业务动作所需的**最小页面跳转次数、必点交互步数、首屏可见核心模块数、横向滚动溢出率**。这类指标由前端 DOM 结构与路由逻辑直接决定，可在当前环境中 100% 精确测定。
2. **真人工程师端到端任务耗时指标（需按实验规程实测）**：
   - 指真人售前/系统工程师完成一份完整工程方案所需的秒数/分钟数及主观认知负荷评分（NASA-TLX）。此类指标受真人阅读速度与 DSH 实时大模型推理延迟影响，**在未采集真实真人对照样本前，绝不伪造“人工耗时缩短 XX%”的结论**，而是提供可直接执行的标准化测量规程与记录表。

---

## 2. 已实测的确定性交互路径收敛对比（Before vs. After）

以下数据基于同一合成验收项目（`船舶冷链多温区智能监测与报警系统（合成示范）`，`1440×1280` 桌面视口）在优化前（`feat/v4-guided-discovery` 基准）与优化后（`feat/v4-ux-workbench-optimization`）的真实 DOM 与交互路径测定：

| 核心高频工程任务 | 优化前（Baseline）交互路径与摩擦 | 优化后（Optimized）交互路径与改进 | 确定性步骤/跳转变化 |
| :--- | :--- | :--- | :--- |
| **T1：在任意工作区感知全流程 7 阶段进度与过期阻塞点** | 需返回 `#/overview` 查看总览，并分别点击 `#/discovery`、`#/solution`、`#/cost`、`#/deliver` 逐页检查是否有审核失效（4~5 次页面切换） | 顶部常驻 7 步 `WorkflowStepper` + `.phase-banner` 上游依据失效联动横幅，任意页面一眼可见全部 7 阶段状态并可 1 次点击直达失效阶段 | 跨页巡检跳转从 **4~5 次降至 0~1 次** |
| **T2：在第 5 阶段（综合与决策）审阅第二轮重组路线并执行 Human Gate 确认** | 进入 `#/solution` 后首屏被第一轮 4 张初筛大卡片占满，需向下滚动约 `900px` 才能看到第二轮综合重组路线与决策面板 | 当存在第二轮综合结果时自动置顶「第二轮：研究综合与路线重组（最终候选）」，第一轮初筛自动折叠为 1 行摘要栏，首屏同屏即可看到重组路线、当前已确认标识与决策状态卡 | 首屏无效滚动距离从 **~900px 降至 0px（首屏直达）** |
| **T3：横向比选 4~6 条候选技术路线的组成、优势、风险与待核实项** | 仅支持双列卡片流纵向堆叠，需上下反复滚动比对不同路线的风险与未知项 | 新增 `卡片视图 / 对比矩阵` 分段切换器，1 次点击即可在同一结构化表格中横向对比全部候选路线的 6 个核心维度 | 切换为 **1 屏全量矩阵横向对比** |
| **T4：将已维护的 N 项设备配置转化为 BOM 成本明细行** | 需手工逐行点击「新增成本行」、输入名称/单位、勾选关联配置并切换为 `跟随配置`（每项配置约需 6~7 次点击与输入，4 项配置需 24+ 步操作） | 成本页自动检测未关联 BOM 的有效配置项并展示提示条，点击「按配置一键生成 BOM 行」即可自动建立带 `follow_config` 联动的成本行草稿 | 4 项配置建 BOM 操作从 **24+ 步手工录入收敛为 1 次点击 + 单价补全** |
| **T5：在文档与交付页审阅并接受多章节 AI/数据同步建议（Proposal）** | 需逐节寻找带有建议标识的章节并逐个处理 | 章节内嵌高对比度 `.proposal-banner` 预览盒，同时顶部提供一键接受全部章节建议或逐节接受/拒绝的双模操作 | 批量审阅操作收敛为 **1~2 次点击** |

## 3. 真人工程师效率对比测试方案（标准化实验规程）

若团队在参赛答辩或内部验收中需补充真人耗时对比数据，请严格按照以下 **A/B 交叉平衡实验设计（Counterbalanced Within-Subjects Protocol）** 在 Windows 11 本机 DSH 环境中执行：

### 3.1 实验控制变量（确保公平性）
1. **固定模型路由与思考强度**：两组测试必须绑定完全相同的 DSH 模型与 `reasoningEffort`（例如固定 `qwen3.8-max / medium`），或使用相同的确定性离线 Replay Fixture，并将**“模型推理等待时间（Model Latency）”**与**“工程师界面操作与审阅时间（Human UI Interaction Time）”**分开计时。
2. **等难度脱敏测试案例（2 套合成工程案例）**：
   - **案例 α**：船舶四冷藏舱 0~4°C 连续监测与断网缓存补传方案（7 条需求、2 条固化支撑、4 条初筛路线、2 份定向研究、4 项配置、4 行 BOM、3 节 Word 模板）。
   - **案例 β**：化工罐区厂界四点激光甲烷监测与声光联动方案（同等规模：7 条需求、2 条固化支撑、4 条初筛路线、2 份定向研究、4 项配置、4 行 BOM、3 节 Word 模板）。
3. **被试分组（消除学习效应）**：
   - 邀请 4~6 名熟悉售前方案业务的工程师，分为两组：
     - **Group 1**：先用【优化前版本 + 案例 α】，再用【优化后版本 + 案例 β】。
     - **Group 2**：先用【优化后版本 + 案例 α】，再用【优化前版本 + 案例 β】。

### 3.2 5 个标准计时任务节点（Task Checkpoints）
| 任务编号 | 标准任务描述 | 起点事件 | 终点事件 | 重点观测指标 |
| :--- | :--- | :--- | :--- | :--- |
| **CP-1** | **需求访谈与简报确认** | 进入 `#/discovery` | 完成 `marketpilot_v4_brief_confirm` 人工确认 | 净界面交互耗时（秒）、切换对比提议次数 |
| **CP-2** | **资料上传与 2 条支撑摘要固化** | 进入 `#/change` | 2 条 `supportNotes` 全部变为 `fixed` | 原文摘录定位一次成功率、净操作耗时（秒） |
| **CP-3** | **初筛 → 2 方向研究 → 二次综合与路线确认** | 点击开始初筛 | 完成 `marketpilot_v4_route_confirm` 人工确认 | 扣除模型等待后的净人工审阅与导航耗时（秒）、迷航回退次数 |
| **CP-4** | **4 项设备配置录入与 BOM 成本草稿审核** | 切换至设备配置 | 完成 `cost_draft` 审核 | 建 BOM 点击次数、净操作耗时（秒） |
| **CP-5** | **模板撰写、章节审阅、导出 DOCX 与发布 V1** | 进入 `#/deliver` | 成功下载 `.docx` 并发布 `V1` 基线 | 章节建议审阅耗时（秒）、三态理解准确率 |
